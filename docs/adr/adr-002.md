# ADR-002 : Base de données — PostgreSQL

- Statut : Accepté
- Date : 2026-11-03

## Contexte
Le domaine (paie vétérinaire) exige un stockage relationnel structuré :
employés, pointages, congés, banques, avec intégrité référentielle (FK) et
transactions (la paie ne tolère pas les incohérences). Le cours exige SQL.
Déploiement auto-hébergé sur ThinkCentre (Debian 12).

## Décision
**PostgreSQL** (v15), auto-hébergé sur le ThinkCentre.

## Alternatives considérées
- **SQLite** : zéro serveur, idéal pour proto, mais limites de concurrence et
  de typage ; insuffisant pour une app multi-utilisateur en production.
  Rejeté.
- **MySQL / MariaDB** : viable, mais PostgreSQL offre un meilleur support de
  l'intégrité, des types et des extensions. Rejeté (préférence PostgreSQL).
- **MongoDB (NoSQL)** : pas de schéma relationnel → on perd FK et contraintes
  essentielles à la paie. Inadapté au domaine. Rejeté.

## Conséquences
- Intégrité référentielle, transactions ACID → sécurité de la paie.
- Coût : installation/administration (acceptable sur ThinkCentre auto-hébergé).
- Schéma documenté dans `docs/schema-v1.sql` (commenté, validé cliente).
