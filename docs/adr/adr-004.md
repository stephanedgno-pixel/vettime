# ADR-004 : Authentification et gestion des rôles

- Statut : Accepté
- Date : 2026-11-17

## Contexte
VetTime doit authentifier les utilisateurs (employés, gestionnaires, administrateurs)
et contrôler l'accès selon les rôles (`roles` + `utilisateurs.role_id`, voir
`docs/schema-v1.sql`). Le blogue 1 (Jalon 1) laissait cette décision en suspens
(sessions sécurisées vs JWT). Or l'application est *server-rendered*
(FastAPI + Jinja2 + HTMX, ADR-001) : il n'y a pas de SPA séparée consommant une
API REST. L'exigence du cours couvre explicitement l'authentification et les rôles.

## Décision
- **Sessions en cookie `httpOnly` + `Secure` + `SameSite`** pour maintenir l'état
  d'authentification (le cookie n'est pas lisible par JavaScript, limitant le vol
  de session via XSS).
- **Mots de passe hachés avec bcrypt** (jamais en clair, jamais dans le dépôt —
  `.env` gitignoré ; rôles DB tournés, voir `docs/problemes.md`).
- **Tokens CSRF** sur tous les formulaires HTMX en POST (protection contre la
  falsification de requêtes inter-sites sur les actions sensibles : approbation de
  congé, correction de poinçon, administration).
- **Pas de JWT Bearer** : pour une application server-rendered, les sessions
  suffisent ; un JWT n'aurait apporté que de la complexité (CORS, refresh tokens)
  sans besoin réel.

## Alternatives considérées
- **JWT Bearer + SPA** : adapté à une SPA, mais on a rejeté la SPA (ADR-001) ; un
  JWT sans SPA ajoute la configuration CORS et la gestion de refresh tokens pour
  rien. Rejeté.
- **OAuth / connexion sociale** : utile pour des comptes grand public, surkill pour
  un périmètre clinique fermé à quelques rôles. Rejeté.
- **Sessions sans CSRF** : plus simple, mais expose les actions sensibles au CSRF.
  Rejeté — CSRF obligatoire.

## Conséquences
- Pas de CORS à configurer (même origine, rendu serveur).
- Déconnexion immédiate (invalidation du cookie de session) ; pas de côté « token
  encore valide » à gérer.
- Les rôles pilotent l'accès aux routes sensibles (correction de poinçon,
  approbation, administration) — aligné sur le modèle `schema-v1.sql`.
- Coût : hachage bcrypt à la connexion (négligeable, pas d'impact perceptible).
